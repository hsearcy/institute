Where the LLM lives in the loop

1. Kid touches a math gate in the world
2. App asks Backend: "next problem for profile=Sam, context=spell-cast, eligible-skills=[+within10, skip-2]"
3. Backend's Tutor Service queries SRS + mastery → narrows pool → asks LLM:
   "Pick a problem from this pool, phrase it for a 6yo, here's recent history"
4. LLM returns: { skill: "+within10", problem: "3 + 4", phrasing: "If you cast 3 sparks then 4 more, how many sparks fly?", expected_answer: 7 }
5. App displays + tutor TTS speaks
6. Kid voice answer → STT → normalizer → "7"
7. App marks correct/wrong, updates local mastery, queues sync event
8. Tutor reaction (TTS) — "Yes! Sparks fly!" or "Almost — let's count: 3, 4, 5, 6, 7..."

Why three deployables

  • Kid app (Expo) — needs to work offline (couch, car, bad wifi). Local DB is canonical for kid-facing state.
  • Rails backend — your wheelhouse. Hosts parent dashboard. Centralizes AI calls (kid app never holds API keys). Owns long-term analytics.
  • AI providers — swap implementations without touching the rest. Dev-mode uses managed APIs (fast iter, no infra). Prod-mode self-hosted.
