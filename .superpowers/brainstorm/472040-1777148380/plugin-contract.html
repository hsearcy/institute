Section 2: Mini-game plugin framework

Every mini-game is a plugin implementing one contract. Engine + LLM choreograph; plugin renders.

The contract — every mini-game implements this

// each mini-game ships as a folder under /minigames/<id>/
// e.g. /minigames/spell-cast/{ manifest.ts, scene.tsx, evaluate.ts }

export const manifest = {
  id: "spell-cast",
  title: "Spell Cast",
  // Which math skills can this template target?
  supportedSkills: ["skip_count_2", "skip_count_5", "skip_count_10", "sequence_next"],
  // What parameters does the LLM fill to instantiate a round?
  paramSchema: {
    enemyType:        "enum: goblin | slime | ghost",
    sequence:         "number[] (target answers, in order)",
    sequencePrompt:   "string (e.g. 'count by 2s starting at 2')",
    hpPerCorrect:     "int (default 1)",
    timeLimitSeconds: "int? (optional)"
  },
  // Asset bundle this scene needs (preloaded by engine)
  assets: ["models/goblin.glb", "models/slime.glb", "fx/spark.glb", "audio/zap.mp3"]
};

// React component for the 3D scene + UI overlay.
// Receives the populated round from the engine.
export function Scene({ round, onAnswer, onComplete }: SceneProps) { ... }

// Pure function: was this voice/text answer correct *for this step* of the round?
export function evaluate(round, currentStep, answerText): EvalResult {
  return { correct: boolean, normalized: number, partial?: boolean };
}

Lifecycle of one round

Engine: pick template
→
LLM: fill params
→
Engine: validate vs schema
→
Mount Scene
→
Tutor speaks prompt (TTS)
→
Voice answer → evaluate()
→
Scene reacts (anim/fx)
→
onComplete → mastery update + sync event

Concrete example — Spell Cast round

What the LLM returns

{
  "templateId": "spell-cast",
  "skill": "skip_count_2",
  "difficulty": 0.35,
  "params": {
    "enemyType": "goblin",
    "sequencePrompt":
      "Cast sparks counting by 2s, starting at 2!",
    "sequence": [2, 4, 6, 8, 10],
    "hpPerCorrect": 1
  },
  "tutorIntro":
    "A goblin! Quick, cast sparks by 2s to defeat it!"
}

What happens on screen

  • Goblin model spawns (5 HP)
  • Tutor says intro (TTS)
  • Mic auto-on, kid says "two"
  • evaluate → correct, spark FX, goblin -1 HP
  • Repeat for 4, 6, 8, 10
  • Goblin defeated → loot drops → onComplete
  • One wrong → tutor scaffolds: "Almost — after 4 comes...?" (does NOT count as a fail unless 2x in a row)

Why this shape

  • Decouples engine from games. New mini-game = new folder. Zero engine changes.
  • LLM only fills schema. It cannot generate arbitrary code that runs on device — safer, deterministic, testable.
  • Schema validation rejects malformed LLM output → fall back to a hand-authored round if generation fails.
  • Skill targeting is explicit. Engine knows which templates can serve which skills, so SRS scheduling has options.
  • Tutor dialogue is per-round, not hard-coded. "Spark goblin" today, "ice goblin" tomorrow — same template, fresh feel.

Alternative I considered & rejected

"LLM writes plugin code on demand" — appealing but: arbitrary code execution on a kid's tablet, no testability, performance unpredictable, can't review. Templates-with-schemas gives 90% of the flexibility with 0% of the risk.

V1 plugins (4 games)

Spell Cast sequences, skip-counting, +/− chain Block Tower addition, sums to N Cookie Share equal sharing, beginning division, counting Door Code single-shot +/− gates (the in-world chest pattern)
